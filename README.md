# 1. ОБЩИЕ СВЕДЕНИЯ

## 1.1. Полное наименование системы

Полное наименование разрабатываемого программного обеспечения:

**«Program for Automating reporting on Work Shift» (Программа для автоматизации отчетности по рабочим сменам)**.

Краткое наименование системы — **PAWS**.

## 1.2. Основание для разработки

Основанием для разработки программного обеспечения является необходимость автоматизации процессов учета рабочих смен сотрудников, хранения сведений о выполненных работах и формирования отчетной документации.

## 1.3. Заказчик и разработчик

Заказчиком программного обеспечения является **Волгоградский государственный технический университет (ВолгГТУ), кафедра «ПОАС»**, учебный проект.

## 1.4. Плановые сроки выполнения работ

Сроки разработки, тестирования и ввода программного обеспечения в эксплуатацию до конца третьего семестра.

## 1.5. Порядок оформления и предъявления результатов

Результатом разработки является работоспособная программа, обеспечивающая автоматизацию учета рабочих смен и формирование отчетности.

В процессе разработки должны быть выполнены:

- проектирование структуры программного обеспечения;
- разработка пользовательского интерфейса;
- реализация функциональных возможностей системы;
- разработка подсистемы хранения данных;
- реализация формирования отчетов;
- тестирование программного обеспечения;
- устранение выявленных ошибок;
- подготовка программного обеспечения к эксплуатации.


# 2. НАЗНАЧЕНИЕ И ЦЕЛИ СОЗДАНИЯ СИСТЕМЫ

## 2.1. Назначение системы

Программа предназначена для автоматизации процессов учета рабочих смен сотрудников, регистрации сведений о выполненной работе, хранения информации о сменах и формирования отчетной документации.

Программа должна обеспечивать централизованное хранение информации о рабочих сменах и предоставлять пользователю возможность оперативного получения необходимых сведений.

## 2.2. Цели создания системы

Основными целями создания программы являются:

- сокращение времени на оформление отчетности по рабочим сменам;
- уменьшение количества ошибок при ручном заполнении отчетных документов;
- автоматизация процесса учета рабочих смен;
- обеспечение централизованного хранения информации;
- повышение оперативности получения отчетных данных;
- обеспечение удобного просмотра и обработки информации;
- упрощение подготовки итоговых отчетов.

## 2.3. Задачи системы

Для достижения поставленных целей программа должна обеспечивать решение следующих задач:

1. ведение информации о сотрудниках;
2. регистрация рабочих смен;
3. внесение сведений о выполненных работах;
4. редактирование и просмотр информации о сменах;
5. поиск необходимых записей;
6. хранение информации в базе данных;
7. формирование отчетов за выбранный период;
8. предоставление итоговой информации пользователю;
9. обеспечение сохранности введенных данных.


# 3. ХАРАКТЕРИСТИКА ОБЪЕКТОВ АВТОМАТИЗАЦИИ

## 3.1. Общая характеристика объекта автоматизации

Объектом автоматизации является процесс учета рабочих смен сотрудников и подготовки отчетности по результатам их работы.

До внедрения программного обеспечения часть операций может выполняться вручную с использованием бумажных документов или электронных таблиц. Такой способ ведения учета требует значительных временных затрат и может приводить к возникновению ошибок при переносе и обработке информации.

Разрабатываемая программа предназначена для автоматизации указанных операций.

## 3.2. Автоматизируемые процессы

В рамках системы автоматизируются следующие процессы:

- регистрация и изменение сведений о сотрудниках;
- регистрация начала и окончания рабочих смен;
- автоматический расчет продолжительности рабочей смены;
- внесение и хранение сведений о выполненных работах;
- просмотр истории рабочих смен;
- корректировка ранее введенной информации;
- поиск рабочих смен по сотруднику и временному периоду;
- формирование ежедневного отчета по рабочим сменам за выбранную дату;
- формирование сводного отчета за выбранный период с расчетом итогового количества смен и общей продолжительности работы.

## 3.3. Основные информационные объекты

В системе должны использоваться следующие основные информационные объекты:

**Сотрудник** — сведения о работнике, участвующем в выполнении рабочих смен.

**Рабочая смена** — сведения о конкретном периоде работы сотрудника, содержащие временную метку начала смены, временную метку окончания смены, рассчитанную продолжительность смены и связанные с ней сведения о выполненных работах.

**Выполненная работа** — сведения о работах, выполненных сотрудником в течение рабочей смены.

**Отчет** — сформированный системой документ, содержащий сведения о рабочих сменах и выполненных работах. Система должна поддерживать ежедневный отчет за выбранную дату и сводный отчет за выбранный период.

## 3.4. Пользователи системы

Основными пользователями программы являются сотрудники, ответственные за ведение учета рабочих смен и подготовку отчетной документации.

В зависимости от принятой организации работы могут предусматриваться следующие категории пользователей:

- сотрудник — ввод и корректировка информации о рабочих сменах;
- руководитель — просмотр информации и получение отчетов;
- администратор — настройка и обслуживание программного обеспечения.


# 4. ТРЕБОВАНИЯ К ПРОГРАММЕ

## 4.1. Общие требования

Программное обеспечение должно быть разделено на функциональные модули, отвечающие за пользовательский интерфейс, обработку данных, работу с базой данных, формирование отчетов и управление доступом пользователей.

Взаимодействие пользователя с основными функциями программы должно осуществляться через графический пользовательский интерфейс.

Для выполнения штатных операций системы пользователь не должен непосредственно изменять содержимое базы данных, программный код или конфигурационные файлы.

Перед сохранением введенных пользователем данных система должна выполнять проверку обязательных полей и допустимости введенных значений.

Права доступа к функциям программы должны определяться ролью авторизованного пользователя.

## 4.2. Требования к функциональным характеристикам

Программа должна обеспечивать выполнение следующих функций:

### 4.2.1. Авторизация пользователей

Система должна обеспечивать идентификацию пользователя при входе в программу.

В зависимости от категории пользователя должны предоставляться соответствующие права доступа к функциям системы.

### 4.2.2. Ведение данных о сотрудниках

Добавление сведений о сотрудниках:

1. уникальный идентификатор сотрудника;
2. фамилия, имя, отчество;
3. должность;
4. статус сотрудника (активен/деактивирован);
5. дата приема на работу;
6. контактные данные.

Должны быть предусмотрены:

- просмотр сведений о сотрудниках;
- изменение сведений;
- удаление или деактивация записей в соответствии с установленными правами доступа;
- поиск сотрудника по заданным параметрам.

### 4.2.3. Учет рабочих смен

Программа должна обеспечивать:

- создание записи о рабочей смене;
- выбор сотрудника, для которого регистрируется смена;
- указание временной метки начала смены;
- указание временной метки окончания смены;
- автоматический расчет продолжительности смены как разницы между временем окончания и временем начала;
- внесение сведений о выполненной работе;
- сохранение введенной информации;
- редактирование ранее созданной записи;
- просмотр истории рабочих смен.

При сохранении записи система должна проверять наличие обязательных данных и корректность временного интервала. Временная метка окончания смены должна быть позже временной метки начала смены.

### 4.2.4. Поиск и просмотр информации

Программа должна обеспечивать поиск рабочих смен по заданным параметрам.

Пользователь должен иметь возможность просматривать информацию за выбранный период, а также получать сведения по конкретному сотруднику.

### 4.2.5. Формирование отчетности

Программа должна обеспечивать формирование двух типов отчетов:

- **ежедневный отчет** — формируется за выбранную календарную дату и содержит сведения о рабочих сменах, зарегистрированных за эту дату;
- **сводный отчет за период** — формируется за заданный пользователем временной интервал и содержит сведения обо всех соответствующих рабочих сменах, а также итоговые показатели.

При формировании каждого типа отчета пользователь должен иметь возможность задать сотрудника или группу сотрудников.

Отчет должен содержать:

- сведения о сотруднике;
- временную метку начала смены;
- временную метку окончания смены;
- продолжительность смены;
- сведения о выполненных работах.

Сводный отчет дополнительно должен содержать общее количество смен и суммарную продолжительность отработанного времени за выбранный период.

### 4.2.6. Экспорт отчетов

Программа должна обеспечивать сохранение сформированных отчетов в электронном виде.

Отчет формируется автоматически на основании данных, содержащихся в базе данных, с учетом заданных пользователем параметров: типа отчета, временного периода и выбранного сотрудника или группы сотрудников.

Поддерживаемые форматы экспорта:

- **PDF** — для просмотра, передачи и печати отчета;
- **XLSX** — для просмотра и дальнейшей обработки данных средствами табличных редакторов.

Экспортируемый отчет должен содержать:

- наименование и тип отчета;
- дату и время формирования отчета;
- выбранный отчетный период;
- сведения о сотруднике или группе сотрудников;
- табличную часть со сведениями о рабочих сменах;
- временные метки начала и окончания каждой смены;
- продолжительность каждой смены;
- описание выполненных работ;
- итоговые показатели, предусмотренные для соответствующего типа отчета.

После выполнения экспорта система должна создавать файл выбранного пользователем формата и уведомлять пользователя о результате операции.

## 4.3. Требования к надежности

Программа должна обеспечивать устойчивую работу при штатной эксплуатации.

Не допускается неявная и несанкционированная потеря данных при ранее прописанных операциях.

При возникновении ошибок программа должна информировать пользователя о невозможности выполнения операции и, по возможности, предоставлять сведения о причине ошибки.

Должны быть предусмотрены средства резервного копирования данных.

## 4.4. Требования к информационной безопасности

Доступ к функциям программы должен осуществляться в соответствии с установленными правами пользователей.

Должна быть обеспечена защита данных от несанкционированного изменения и удаления.

Пароли и иные данные, используемые для авторизации, не должны предоставляться пользователям, не имеющим соответствующих прав доступа.

## 4.5. Требования к пользовательскому интерфейсу

Пользовательский интерфейс программы должен удовлетворять следующим требованиям:

- после авторизации пользователю должны отображаться только разделы и операции, разрешенные его ролью;
- основные разделы системы должны быть доступны из главного навигационного меню;
- переход от главного экрана к операциям создания рабочей смены, поиска смен и формирования отчета должен требовать не более трех последовательных переходов;
- каждое поле ввода должно иметь текстовое наименование;
- обязательные для заполнения поля должны иметь визуальное обозначение (выделенный текст с надписью: «Обязательно заполнить»);
- элементы управления должны иметь наименования, соответствующие выполняемой операции: «Сохранить», «Изменить», «Удалить», «Сформировать отчет», «Экспортировать»;
- при вводе некорректного значения система должна запрещать сохранение данных и выводить сообщение с указанием поля, содержащего ошибку;
- после успешного добавления, изменения или удаления данных система должна выводить сообщение о результате выполненной операции;
- перед удалением существующей записи система должна запрашивать подтверждение пользователя;
- формы создания и редактирования записи должны отображать текущие значения всех редактируемых полей;
- недоступные пользователю в соответствии с его ролью операции не должны отображаться либо должны быть недоступны для выполнения.

## 4.6. Требования к условиям эксплуатации

Программа должна функционировать в стандартном режиме эксплуатации на рабочих местах пользователей.

Рабочее место пользователя должно быть оснащено персональным компьютером, соответствующим минимальным требованиям используемой программной платформы:

- **процессор:** 2-ядерный процессор с тактовой частотой не менее 2,0 ГГц;
- **оперативная память:** не менее 4 ГБ;
- **свободное место на накопителе:** не менее 2 ГБ для установки программы и хранения служебных файлов;
- **монитор:** разрешение не менее 1280×720 пикселей;
- **клавиатура и мышь:** стандартные устройства ввода;
- **сетевое подключение:** наличие подключения к локальной сети или сети Интернет;
- **операционная система:** Windows 10 или более поздняя версия Windows, поддерживающая используемую программную платформу;
- **программная платформа:** наличие компонентов и библиотек, необходимых для функционирования программы;
- **права пользователя:** наличие необходимых прав для запуска программы и доступа к используемым данным.

Эксплуатация программы должна осуществляться в соответствии с руководством пользователя и установленным порядком работы с информационной системой.
